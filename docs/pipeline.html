PIPELINE · PROMPTS

流水线与提示词

长庚 Vesper 把小说原文做成短剧。输入是一份 txt 原文（可追加多份），产出是每集一条合成版视频。流程依次为：原文 → 分集 → 资产 → 节拍 → 分镜 → 首帧 / 视频 / 配音 → 合成。

分集、提取资产、写节拍、拆分镜、逐镜精写与审查调用文本模型；设定图与首帧调用图像模型；视频调用视频模型，可同时生成声音；选择单独配音时，台词交给配音模型；合成在本机用 ffmpeg 完成，不调用模型。

全程在三处停下等人确认：分集定稿、资产锁定、节拍确认。此后的首帧、视频与配音可以逐镜发起、看过一镜再做下一镜，也可以整集按镜序依次生成。

本页上半部分是工作流，下半部分逐节列出每一步发给模型的提示词全文。

步骤说明
0 导入上传原文，设定作品名、画幅、画风、单集目标时长、音轨、单镜时长、末帧参考
1 分集填了集数时，把一份原文切成若干集，产出每集标题、概要与末句，由代码按末句定位切分点。不填集数时，一份原文就是一集
2 提取资产从原文提取角色、场景、道具，写出外貌、着装、音色、空间、外观等文字描述
3 设定图按资产描述出图：角色先出全身，再以全身为参考出半身特写、三视图、表情集、服装细节；场景出场景空镜，道具出道具单品
4 写节拍把一集原文改编为节拍序列，区分展开演与旁白带过，台词在这一步定稿
5 拆分镜把节拍拆为镜头表：景别、机位、运镜、情绪、衔接、台词分配、引用的资产
审查第 4、5 步完成后各自动执行一次，也可手动发起：模型以没读过原著的观众视角复述剧情，列出看不懂、接不上的地方。只出报告，不改内容
6 逐镜精写为一镜写成品提示词：首帧画面 image_prompt、运动过程 motion_prompt、声音 sound 与每句台词的念法。生成某一镜的首帧或视频时，这一镜还没有提示词就先写；也可以单镜重写
7 首帧以 image_prompt 与参考图生成首帧。画面来源为「参考图」的镜头跳过
8 视频以首帧（或参考图）与 motion_prompt 生成视频
9 配音仅单独配音时执行：台词原文送配音模型。视频自带声音时由视频模型同时出声
10 合成按镜序拼接视频，单独配音时叠加配音，产出这一集的合成版。画面按画幅等比放大铺满，居中裁去多出的边；片头、片尾与衔接为黑场（join 为 fade）的接缝淡入淡出；各镜响度过高的压低，有台词而过低的抬高

03 · EDITING

怎么改提示词

提示词全部写在 server/src/pipeline/prompts.ts，其中的字符串逐字发给模型。下文每节标题旁的函数名就是该文件中的导出函数；只想对单次生成补一句要求时，填「其他」即可，不必改代码。

打出全文。下面的命令用固定样例渲染全部模板，不连接数据库，每行前面是字数；末尾加模板 id 只打一份，id 写错会列出全部可选值。改前改后各存一份，用 diff 对比。

bun run server/src/tools/dump-prompts.ts
bun run server/src/tools/dump-prompts.ts shot_prompt

检查。改完运行下面的命令，依次执行类型检查、lint、knip、测试与构建；提示词的断言在 server/test/prompts.test.ts 与 server/test/preview.test.ts。

bun run check

不能动的格式约定

  • 「输出 JSON：」示例。回复按 zod schema 解析，写节拍与审查还随请求发送同构的 JSON Schema；改字段要同时改解析代码。
  • ends_with 逐字抄写。代码靠它在原文中定位分集切点与每拍对应的原文段。
  • 资产描述原样写入。设定图、参考图说明里的资产描述取自锁定版，逐字写入，不改写；改写一次相当于换了一个对象。
  • 参考图说明的顺序与实际发送的参考图一致。说「@图片3 是某某」而第 3 张是别人，比少挂一张更糟。
  • 参考图说明里每张图的用途。删掉后模型会照搬设定图的构图取景。
  • 画幅不写进提示词。画幅只通过请求参数传给模型。

STEP 2 · TEXT

提取资产 assetsPrompt

这里写的描述是后面所有画图的文字依据。节拍确认后可以再提取一次，补上会开口的角色；已有的同名资产不动，只新增。

结构任务 + 提取标准 + 角色 / 场景 / 道具细则 + 人工指定 + 已提取名单 + 字段说明 + 额外要求 + 原文

system：你是美术指导，从原文中挑出需要固定形象、会在多个镜头里反复出现的人物、场景与道具。只输出 JSON，不要解释。
从下面的原文中挑出**需要固定形象**的{提取类别}。未选时为全部三类
怎么判断要不要提取：这个名字指的是一个固定的具体对象，**会真的出现在画面里**，能画成一张设定图，在后面的镜头里反复使用。 要不要提取，看它在剧情里起不起作用，不看出现几次：戏份少但推动剧情的要提取，出现多但与剧情无关的不用提取。 每多一样，后续每一镜就多一张要管的参考图，也多一笔生成费用，不要凑数。
## 人物（characters） - 要提取：主角，以及画面里要认出脸的配角；推动剧情、反复出场的怪兽、机甲、灵兽这类非人形角色也算 - 不用提取：无名路人、群像（「围观群众」「学生们」）、泛指（「敌人」「守卫」）、只当背景的载具 - tier：lead 为主角与核心对手，support 为其余要认出脸的 - 提取几个由剧情定。没提取的人物照样可以说台词，只是长相不会前后统一选了角色
已定稿的改编剧本里，这些名字会开口说话：{已确认节拍中的说话人}。 其中指具体某个人的**都要提取**，哪怕原文里只出现一两次，因为他们会真的出现在画面上。 泛指与群像（如「某某队员」「众人」）仍然不用提取。节拍已确认
## 场景（scenes） - 要提取：剧情会反复回到、观众需要认出「又回到了这个地方」的固定空间 - 不用提取：只路过一次的地方、泛指的环境（「走廊」「街上」）、纯天空纯海面这类无结构的背景 - **一个场景只装一个镜头拍得下的连续空间**。通道、厅堂、台阶、殿内要分成四个场景； 合成一个「金字塔内部」来写，画出来会是上下两半拼起来的图 - 提取几处由剧情定。没提取的地方照样能拍，按那一镜的环境描述现画选了场景
## 道具（props） - 要提取：推动剧情、并且在多个镜头里出现的关键物件，比如主角的武器、贯穿全篇的信物、关键装置 - 不用提取：一次性的消耗品、背景陈设、泛指的器物（「枪」「杯子」） - 提取几件由剧情定，拿不准就不提取选了道具
## 人工指定（和上面的规则冲突时，以这里为准） - 一定要提取：{包含}。出现次数再少也要提取，放进它所属的那一类 - 不要提取：{排除}。出现次数再多也不提取，三类里都不要出现填写了包含或排除
## 已经提取过的（换个叫法也算同一个，不要再输出） {作品内已有资产名}作品已有资产
## 字段 外观类的描述都要过图像模型的内容审核：血迹、伤口、尸骸、利器刺入人体这类字眼会让这张设定图直接被拒。同样的东西改用形制、材质、颜色、磨损、光泽来写。
人物： - name：正式称呼，取原文中最常用的那个；aliases：原文中出现过的其他称呼 - tier：lead 或 support - form：human 为人形，creature 为怪兽、机甲这类非人形 - identity：身份与人物关系，一两句 - traits：**外貌辨识特征**，只写画得出来的东西（年龄段、发型发色、眼睛、体型、显著特征）。不要写性格 - 非人形的 traits 写清体态（几足、站姿、尺度）和脸：眼睛、口部与头部轮廓，outfit 留空 - 性别、年龄这类原文写明的，照原文写，traits 和 voice 都不能跟它矛盾；原文没写的才自己补 - outfit：默认着装，写清款式与颜色。只写穿戴在身上的衣物与配饰， 手里拿的武器和随身物件不写，它们归到道具里；两处各写一遍，会画成两件不同的东西 - outfit 只写一身：剧中换了一身明显不同的衣服（便服换官服、常服换嫁衣），出场最多的那身写进 outfit， 其余每身写进 costumes：name 是这身装扮的叫法（「官服」），outfit 照上面的写法。只是加件外衣、摘了帽子不算换装 - voice：音色描述，如「少年音，清亮，语速偏快」 - appearances：在原文中出现的大致次数选了角色
场景： - name：这个地方的称呼；aliases：其他叫法 - description：空间本身——结构、材质、陈设、尺度。只写画得出来的， 且只写**这一处**：出现「…与…交替」「深处还有…」就说明该拆成两个场景 - lighting：默认的光线与时段，如「冷白顶光，全息投影的蓝光，无自然光」 - appearances：在原文中出现的大致次数选了场景
道具： - name：按物件看上去是什么来叫；只在剧情里才有的叫法写进 aliases - description：外观——形制、材质、颜色、尺寸感、显著细节 - holder：归谁所有或谁在用；没有明确归属就留空 - appearances：在原文中出现的大致次数选了道具
这次只提取{提取类别}，其余类别给空数组，哪怕原文里确实有。只选了部分类别
额外要求（和上面的规则冲突时，以这里为准，输出格式照旧）： {其他}
原文： {所选原文}多份时每份前加【文件名】
产出用于
角色 traits设定图「外貌：」、首帧 参考图说明、逐镜精写「出场人物」
角色 outfit设定图「着装：」；这个角色有换装时，拆分镜 角色清单里的「着装：」

写节拍 beatsPrompt

全流程中主要的人工改写环节。台词在这一步定稿，后面各步只按编号引用。代码按每拍的 ends_with 定位原文；最后一拍只改编到原文 80% 以前时，视为回复中途停止，重写一次，仍不足则记一条警告。

system：你是短剧编剧，把小说章节改编成短剧的叙事节拍。改编短剧本来就要删减原文。只输出 JSON，不要解释。
把下面的原文改编成一集短剧的叙事节拍，本集标题《{title}》。
